# Codex 精品宠物制作与投稿指南

简体中文 | [English](../en/submission-guide.md)

Awesome Codex Pet 不是一个只看数量的素材目录。我们希望收录的是角色还原准确、动作语义清楚、透明边缘干净，而且作者与素材使用说明清楚的精品宠物。

这份指南从版本选择、逐动作制作、边缘清理，一直讲到打包、验收、投稿和分享。AI 可以加快制作，但最终质量仍要靠逐帧、逐动作的人工判断。

## 最快的方式：在 ChatGPT 中交给 Codex 完成

网站的**制作指南**和**投稿**菜单都提供**在 ChatGPT 中开始**。点击后会通过 `codex://new?prompt=...` 在 ChatGPT 中打开一条完整的 Codex 任务；ChatGPT 目前仍沿用 `codex://` 作为这类深链接协议。任务会先补齐参考图、名称、作者署名、来源说明和素材使用条件，再读取仓库内置的 Hatch Pet 流程，完成制作、验收和 Pull Request。

也可以把下面这段任务直接交给 ChatGPT：

```text
请帮我制作并投稿一只 Codex 宠物到 https://github.com/legeling/awesome-codex-pet。

开始前先向我索取缺失的角色参考图、宠物名称、作者署名、来源说明和素材使用条件。正式许可证不是必需项；没有正式许可证时，必须明确“仅限非商业使用/禁止商用”，并确认提交者有权投稿。原创、AI 生成或私有来源的素材可以没有公开来源链接。克隆或打开仓库后先阅读 AGENTS.md 和本投稿指南，再严格按照仓库内的 .agents/skills/hatch-pet-v2/SKILL.md 制作，不要假设用户环境已经全局安装这个 skill。

请把九组标准动作分别设计和验收，不要用同一姿势机械复制。检查角色一致性、动作语义、尺寸和基线稳定性，以及深色、浅色、棋盘格背景下的紫边、绿边、青边和洋红边。V2 还要完整验收 16 个顺时针环视方向。

正式目录只能包含 submission.json、pet.json、spritesheet.webp。运行 npm run previews、npm run readmes、npm run validate、npm run lint，并做一次独立安装测试。完成后创建独立分支、提交，并发起一个只包含这只宠物的 PR。
```

AI 辅助不会降低署名和使用说明要求。提交者仍需确认自己有权投稿，并对作者、来源说明和“仅限非商业使用”或正式许可证声明负责。

## 什么叫“精品宠物”

一只值得收录的宠物，至少同时满足下面六点：

1. **角色准确**：脸、比例、配色、轮廓、服装和道具在所有动作中保持一致。
2. **动作清楚**：九组标准动作各有用途，不是把同一组姿势换个名字。
3. **播放稳定**：实际显示尺寸下没有忽大忽小、基线跳动、方向错误或节奏反转。
4. **边缘干净**：深色、浅色和棋盘格背景下都没有紫边、绿边或其他色键残留。
5. **信息可信**：作者、来源说明、分类、合集、标签和素材使用条件真实、完整。
6. **安装可靠**：最终三件套通过预览、校验、Lint 和独立安装测试。

## V1 与 V2 有什么区别

| 版本 | 图集规格               | 运行时字段                            | 动画内容                     | 适用场景               |
| ---- | ---------------------- | ------------------------------------- | ---------------------------- | ---------------------- |
| V1   | `1536x1872`，8 × 9 格  | 省略 `spriteVersionNumber` 或设为 `1` | 9 行标准动作                 | 保留、修复已有旧版宠物 |
| V2   | `1536x2288`，8 × 11 格 | 设置 `spriteVersionNumber: 2`         | 9 行标准动作 + 16 个环视方向 | 新宠物与 V1 升级，推荐 |

两个版本都能收录，也都能安装。新作品默认推荐 V2，因为它能在 Codex 中根据目标位置做出自然的环视反应。

- 维护 V1 时使用 [.agents/skills/hatch-pet-v1](../../.agents/skills/hatch-pet-v1)。
- 新建 V2 或执行 V1 → V2 升级时使用 [.agents/skills/hatch-pet-v2](../../.agents/skills/hatch-pet-v2)。
- 升级本地 V1 时，打开 Codex 的**设置 → 宠物**并点击**更新**。升级会保留已通过验收的九组标准动作，再补上两行方向动作；它不会自动向本仓库投稿。

### V2 的 16 个环视方向

V2 最后两行共 16 格，按 22.5° 间隔顺时针排列：

```text
向上 → 右上 → 向右 → 右下 → 向下 → 左下 → 向左 → 左上 → 回到向上
```

四个正方向必须一眼可辨。中间方向要形成连贯的过渡，不能通过旋转或倾斜整张角色图片来假装视线变化。人物类宠物通常应由眼睛先动，再由眼睑、眉毛、头部、颈部和上半身自然跟随；佩戴或手持的道具也要遵守真实的遮挡和连接关系。

## 九组标准动作要逐一设计

九行标准动作的固定顺序如下：

| 行  | 动作                   | 制作重点                                                 |
| --- | ---------------------- | -------------------------------------------------------- |
| 0   | `idle` 待机            | 用呼吸、眨眼、重心变化保持鲜活，不能像静止贴图           |
| 1   | `running-right` 向右跑 | 明确朝右、步态交替，不要速度线、烟尘和地面阴影           |
| 2   | `running-left` 向左跑  | 明确朝左；只有左右结构完全安全时才镜像右跑               |
| 3   | `waving` 挥手          | 用手、爪、耳朵或身体打招呼，不要悬空波浪线               |
| 4   | `jumping` 跳跃         | 读得出起跳、腾空、回落，角色比例与落脚点保持稳定         |
| 5   | `failed` 失败          | 用表情和姿势表现沮丧；附加效果必须贴着角色且是硬边像素风 |
| 6   | `waiting` 等待         | 表现正在等待授权、帮助或输入，不能像普通待机或审查       |
| 7   | `running` 奔跑         | 表示 Codex 正在忙碌处理，不是另一组左右移动动作          |
| 8   | `review` 审查          | 用视线、歪头、前倾或手部表现检查，不凭空增加无关道具     |

### 每个动作都可以单独精修

不要只写一段“让角色动起来”的总提示词。更可靠的做法是给每一行指定独立目标：

- 先锁定角色身份：头型、五官、标志性花纹、配色、比例、描边和道具。
- 再描述这组动作的起点、峰值和回环方式，而不只是列出姿势名称。
- 明确哪些部位应该动、哪些部位必须稳定，以及道具如何跟随或滞后。
- 用统一的角色高度、下半身锚点和基线检查播放，避免“每帧都好看，连起来却抖”。
- 某一行失败时只返修这一行；某一帧有问题时先修这一帧，不要轻易重做整只宠物。

向左跑不能默认镜像向右跑。可读文字、非对称花纹、惯用手、单侧饰品、光线方向或手持道具一旦会被镜像弄错，就应该单独生成并验收向左动作。

## 紫边、绿边与透明边缘处理

色键抠图后常见绿、青、洋红、紫、粉色边缘残留。它们可能来自背景色溢出、抗锯齿混色、半透明阴影、光晕或二次缩放。

### 先从生成阶段避免污染

- 选择一个不在角色真实配色里的色键背景。绿色头发不要用绿幕，紫色服装不要用洋红或紫幕。
- 要求背景平整、纯色，角色周围没有阴影、光晕、模糊、半透明像素和动作拖影。
- 优先用姿势、表情与轮廓表达动作，不要用速度线、烟尘、落地光效和悬空符号堆效果。

### 再逐帧检查

至少用三种底色看最终结果：

1. 棋盘格：检查透明度、内部透明洞和孤立杂点。
2. 深色背景：检查白边、绿边、青边和浅色光晕。
3. 浅色背景：检查黑边缺口、紫边、洋红边和角色掉色。

同时看正常宠物尺寸与 100%–200% 放大图。接触表和单帧只能发现静态问题，还要播放每组 GIF，确认色边不会只在某一帧闪现。

### 修复时遵守“最小范围”

- 先修单帧，再修单个动作行，只有污染普遍存在时才处理整只宠物。
- 不要全局删除绿色、紫色或洋红色。角色本身可能合法使用这些颜色。
- 对半透明边缘，应从邻近的角色像素重建 RGB，同时保留正确 alpha 和轮廓厚度。
- 清掉孤立色点，但不要把发梢、耳朵、手指、武器尖端和 1–2 px 描边一起侵蚀。
- 清理后重新看静态图与动画，确认没有透明洞、轮廓断裂、颜色变脏、尺寸跳变或基线抖动。

Hatch Pet 生成的 matte-fringe / chroma-despill 报告是定位线索，不等于可以盲目批量删除颜色。最终仍需结合角色真实配色做人眼判断。

## 正式成品只有三个文件

```text
pets/
└── pet-slug--author-slug/
    ├── submission.json
    ├── pet.json
    └── spritesheet.webp
```

- 目录名固定为 `pet-slug--author-slug`。
- `pet.json.id` 必须与目录名完全一致。
- `pet.json.spritesheetPath` 固定为 `spritesheet.webp`。
- `spriteVersionNumber` 必须与图集尺寸匹配。
- `spritesheet.webp` 必须是最终运行时资源，不是过程版。
- QA、参考图、提示词、视频、PNG 中间件和 Hatch Pet 运行目录都不能放进正式宠物目录。

## 分类、作品系列、主题系列与署名

投稿时请提供：

- 主分类、宠物默认名称和简短描述
- 选择只使用默认名称，或同时提供自己确定的中文名与英文名；双语模式在 `submission.json.localized_names` 中同时填写 `zh` 和 `en`
- 作者名或 handle
- 来源链接或来源说明；原创、AI 生成或私有来源可以没有公开链接
- 素材使用条件：可以是正式许可证，也可以是明确的“仅限非商业使用/禁止商用”声明
- 标签，以及可选的作品系列或主题系列 slug

系列和合集都属于仓库元数据，不是网站前端单独维护的名单。根目录 [`collections.json`](../../collections.json) 中，每一项都有明确的类型：

- `franchise`：来自同一款游戏、动画、影视或其他原作的作品系列。宠物标签中也必须包含相同 slug。
- `theme`：按题材、风格或伙伴类型组织的跨作品主题系列。

在 `submission.json` 中填写匹配的 slug。一只宠物可以同时属于多个系列或合集：

```json
{
  "collections": ["genshin-impact", "animal-companions"]
}
```

网站构建时会自动归组。不要为了让宠物出现在某个系列或合集里，再维护一份前端名单；需要新增仓库级系列或主题时，应修改 `collections.json` 的定义。

## 预览、校验与安装测试

先生成动作预览：

```bash
python -m pip install -r requirements.txt
npm run previews
```

预览会生成到 `assets/previews/<pet-id>/`，只作为本地或部署产物，不应放进宠物正式目录，也不需要随贡献者 PR 提交。

然后更新生成内容并完成静态检查：

```bash
npm run readmes
npm run validate
npm run lint
```

最后做一次独立安装测试：

```bash
npm run install:pet -- pet-slug--author-slug --codex-home /tmp/codex-pet-test
```

预期生成：

```text
/tmp/codex-pet-test/pets/<pet-id>/
├── pet.json
└── spritesheet.webp
```

一个 PR 只提交一只宠物，方便审核作者、使用说明、动作与边缘质量，也避免无关文件混入。

PR 提交后，维护者会检查实际渲染的人物方向、动作语义、跑步步态、动画衔接和透明边缘颜色。透明边缘会分别放在棋盘格、深色和浅色背景下检查绿边、紫边、青边、洋红边或其他色键残留。投稿不一定原样合并：维护者可能在合并前修复单帧、动作行、环视方向、最终 `spritesheet.webp` 或元数据，同时保留角色身份和作者署名；视觉变化较大时，可能会请投稿者再次确认。

## 分享与社区共创

每个宠物详情页都会展示作者、来源说明、素材使用条件、完整动作和安装入口。推荐分享详情页，而不是单独转发一张 WebP，这样作者信息不会丢，接收者也能先看动画再安装。

网站分享菜单提供：

- 复制完整页面链接
- 复制已经写好的分享文案
- 复制适合 GitHub、Discord 和文档使用的 Markdown 链接
- 分享到 X、LinkedIn 或调用手机 / 桌面的系统分享
- 在 ChatGPT 中直接打开安装或制作任务

分享时请保留作者署名与原始收录页。好宠物值得被传播，创作者也应该被看见。

PR 合并后，用户无需克隆仓库即可安装：

```bash
curl -fsSL https://raw.githubusercontent.com/legeling/awesome-codex-pet/main/scripts/install-pet.sh | bash -s -- pet-slug--author-slug
```
